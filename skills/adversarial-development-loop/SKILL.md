# Adversarial Development Loop · 对抗式自循环开发

## 核心原则 (Overview)

**任何方案在写下一行代码之前,必须先被一个独立审查者成功证伪过——或至少尝试证伪后幸存。** 决策要经得起对抗,而非依赖实现者的自信。每轮迭代 = 一次「枚举 → 规划 → 对抗证伪 → 修订 → 实现(逐跳追踪) → 测试 → 复盘」闭环,并当场落盘成日志。

**铁律:跳过枚举或对抗步骤 = 流程违规。未经对抗的代码应推倒重来。**

**违反规则的字面,就是违反规则的精神。**

### 用户指令是硬约束,不是参考(最高优先级)

用户给的明确数字/范围/轮次是**指令,不是目标、不是建议、不是"差不多就行"**。

- 用户说"跑 50 轮" → 就跑 50 轮,不是 6 轮后自己判"自然收口点"。
- 用户说"改这 3 个文件" → 就改这 3 个,不是自作主张砍到 1 个再给理由。
- 任何"我觉得可以提前收口/缩减范围"的念头 → **先问:用户给过明确的数字/范围吗?给了就照做,没给就问,不许自己定。**

**单方面缩减用户指令 = 最严重的信任违约,比漏一个 bug 更根本。** 它比"跳过 REFUTE"更严重:后者漏 bug,前者直接不执行用户。

**禁用所有给"擅自收口"背书的合理化**(这些会披着"遵守 skill"的外衣,最难识破):
- ❌ "上下文快满了" → 核实实际用量(harness UI 百分比 / `model.response.diagnostics` 事件),不是凭对话长度猜。没到上限就不是理由。
- ❌ "R4 警告不要凑数" → R4 警告的是**低价值轮次**,不是**轮次数量**。用 R4 给"该收口"背书而用户要的是 50 轮 = 误用规则。
- ❌ "前 N 轮质量高,后面会变低价值" → 那是 R1 的职责(扩张边界找新缺口),不是你缩减轮次的借口。换维度 grep、读 NOT UNDERSTOOD 的 shape,继续。
- ❌ "journal 更新了,可以新会话续跑" → 用户没说换会话。你在替用户做决定。

**唯一允许提前停的情况**:用户明确说"够了"/"可以了"/"停",或真的触及硬上限(上下文将满,且已如实告知用户、由用户确认)。

### 两条互补的防线(缺一不可)

对抗式证伪只能攻破 **known unknowns**(你已知存在缺陷类别:假满分、死代码、配置卫生……),它攻不到 **unknown unknowns**(你和对抗者都不知道存在的合法状态 shape C/D)。因此本 skill 同时强制:

1. **枚举合法状态空间**(Step 0)——把数据能取的所有 shape 强制暴露出来,把 unknown unknowns 变成 known unknowns,作为对抗的输入。
2. **端到端逐跳追踪**(Step 4 内嵌)——任一 fix 都顺着数据流追到所有消费者,防"修了一层、同一份错数据在下一层继续被错读"的单层修复。

光有对抗不枚举,会自信地实现一个漏处理 shape D 的方案并拿到 PASS;光枚举不追踪,会修对 producer 却漏掉第 3 跳的消费者。

### 自我维护纪律(防 skill 自身膨胀,与 Pattern Index 淘汰规则同构)

**改本文件时必读 `references/framework-manual.md`「内核维护纪律」**。要点:加新规则/核查项/案例前,grep 全文找被覆盖/替代/稀释的旧条目 → 合并(留权威定义处,其余改"见 X")或淘汰;iter 案例佐证已有条目时加到该条目旁,不开新条目;**判定指标:一次修改净增 >15 行 ≈ 没执行本纪律,回头 grep 重叠。**

## When to Use / 何时使用

见 frontmatter `description` / `when_to_use`(适用:结论会被当真消费的逻辑、跨层数据、理论缺口/拍脑袋阈值/退化输入二义性;不适用:单行 typo、纯研究、机械重构、无数据流纯局部改动)。

## 一轮迭代(7 主步 + 2 子门:①½ 可达性自检 / ⑤½ DOGFOOD,全部走完)

```
 ⓪ ENUMERATE 找 producer → 穷举合法 shape → 标 UNDERSTOOD/NOT → 读所有 producer 取并集
        │  → 枚举退化输入轴(force=0/空mesh/n=1/空grid)×消费者模块矩阵(防假满分跨轮重发现)
        │  (有合法状态空间的逻辑才强制;纯局部改动可跳过)
        │
 ① PLAN 【先 grep journal】过往同类教训 → 找理论缺口
        │  Explore 策略:先 targeted grep 锁 pattern → targeted Explore → broad 只做收尾 CLEAN
        │  写初版方案(先不实现)
        │
 ①½ 可达性自检门(grep caller + 赋值点 + 注释归属)— 只过滤"路径不可达"类假缺口
        │  通过 → 进 ② ;不通过 → 降级 backlog/弃,不派 REFUTE(省 refuted-subagent token)
        │  边界:只判"会不会执行",不判"对不对/属哪类"——后者必派 REFUTE(iter 69)
        │
 ② REFUTE 派对抗子 agent 证伪【尚未实现】的方案,附带 ⓪ 的 shape + 退化输入矩阵作为攻击面 ─┐
        │  两 agent 矛盾 → 查一手源(tiebreaker),不派第三个                              │
   [blocker 证伪整个方向?]                                                              │
     是 ──→ 停止本方向,回 ① 重选触发点(别在死链路投入)                                  │
     否 ──→                                                                           │
        │ ←─────────────────────────────────────────────────────────────────────────┘
 ③ REVISE 逐条:采纳 / 反驳(理由) / backlog;区分「前置bugfix」与「功能」分开提交
        │
 ④ IMPLEMENT 最小改动集;数值带出处注释;新配置键补全(对称)
        │  【内嵌逐跳追踪】改动 datum 若跨层 → 列 producer→每跳→每消费者,逐跳 ✓/✗,全 ✓ 才许提交
        │  发现某字段 bug → 查同语义字段(跨 struct/跨接口面) + 同 pipeline 兄弟模块(横向 grep)
        │  【5.5 DOGFOOD 每 N 轮/milestone】用真实消费者产物跑,非仓库内 fixture
 ⑤ TEST 每个语义分支 + 回归保护;跑全套 → "X/X（原 N + K）";字符串级证据,不信构建时间戳;
        │  改了 src/X.cpp 必须 build 直接消费它的可执行 target,不只 test target
 ⑥ RETROSPECT + JOURNAL 【变种横向 grep】修一类 bug 立即 grep 同变种 + 按模板追加日志
        │  【Pattern Index 维护】新 pattern 追加进主题级索引(稳定英文关键词)+ journal 末尾写"更新:N/A|新增"
        │  (含 shape 覆盖表 + 退化输入矩阵 + hops 状态表)
     终止条件？ → 否：回 ⓪ 开下一轮（R1 双向：模块级 + 变种级扩张；R4 静默越多置信度越降）
```

### 0. ENUMERATE — 穷举合法状态空间(对抗的前置,不可省)

针对本轮要改的数据/类型,在写方案前先把它的**合法状态空间**列出来。不是"这函数做什么",而是"这份数据能合法地取哪些不同 shape"。仅**有合法状态空间的逻辑**(评分/检测/诊断/解析/recipe/config 组合)强制;纯局部改动可跳过。

1. **找 shape 的源头 = producer**(不是 consumer)。producer 是数据获得形态的地方:dialog 的 collect/submit、parser、enum 的每个构造点、状态机转移表、config 校验器。**多个 producer 就读全部,取 shape 并集**——不同 producer 可能用不同代码产出同一 shape,只读一个会漏路径。
2. **逐行写下 shape 清单**,每 shape 一行,带判别字段。
   ```
   Shape A: Direct  — kind==Direct, mix==0, gradient 空
   Shape B: 2-way   — kind==Mix, component_a/b, mix_b_percent
   Shape C: 3+-way  — kind==Mix, gradient_component_ids 有 N≥3 项
   Shape D: Cycle   — manual_pattern 非空, ids cleared
   ```
3. **每 shape 标 UNDERSTOOD / NOT UNDERSTOOD**,诚实。"瞄过一眼字段名"≠ understood;understood 意味着给定输入你能预测产出哪个 shape 且每个字段是什么。
4. **凡 NOT UNDERSTOOD 的 shape,先读它的 producer 再继续**。不要在没理解某 shape 时去审消费它的下游代码——会推错并漏掉每个相关 bug。
5. **枚举退化输入轴(防假满分跨轮重发现,实战最高频盲区)**:对每个 shape,列出"能生产退化数据/空数据/哨兵值的输入路径"——force=0、空 mesh、n=1、空 grid、字段未初始化、路径不可达。把"退化输入 × 消费者模块"列成矩阵,每格标该格当前返回什么(满分?哨兵?null?)。**任何一个退化输入在多个消费者模块里各自返回"满分/完美"的,就是跨轮重发现的温床**——一轮内必须全部标出,不许靠 backlog 一轮轮串。

产出交给 Step ② 的对抗 agent 作为**攻击面**:清单上每个 shape + 每个退化输入格都要被方案的覆盖范围核对过。

### 1. PLAN — 找理论缺口
**先核实基线(开局必做)**:`git status` + 同名副本清单(`grep -rl <主题>`)+ `diff` 基线——确认"你读的文件就是目标文件"(repo/安装副本可能已发散;曾因基于 stale 副本规划被抓出 3 个 blocker)。
**先 grep journal(强制,防重踩已记录的坑)**:grep 本 journal 的**三个层次**——
1. **Pattern Index / 主题级索引**(若 journal 维护了)— 跨轮的主题级约定(哨兵值语义、已修假满分清单、配置双存储债、可达性失败案例)。这是 ROI 最高的层次:一个主题横跨多轮,一查就知道"这类问题之前怎么定的、修过哪些 site"。**用稳定英文关键词 grep**(如 `sentinel`、`false-perfect`、`config-dual-store`、`reachability`)——自然语言标题会漂移(实测 `grep "1e10 的三种"` 命中 0,因为实际写的是"三种含义"且带反引号;grep 静默返回空 = 你以为没有,其实没匹配上)。措辞不稳 = 等于没索引。
2. **「过程意外」栏**(轮次级)— 上一轮记录的偏差。
3. **Rationalization Table + backlog**(自欺借口 + 待办)。

"可检索"不能只靠记忆——iter 55 仍踩 iter 38 的单位坑、iter 66 仍踩 iter 48 的 fixture 坑,根因都是没 grep。
按下方「目标缺口清单」扫描代码,锁定本轮触发点。**backlog/journal 条目入场前与方案同标尺做 file:line 自检**(iter 11→13:未核实的推断写进 backlog 标成 "finding",差点去修正确的代码)。写初版方案,**先不实现**。

**Explore 策略(token 经济,实战补全)**:扫描可疑区域时按此顺序,别一上来就并行 broad Explore:
1. **先 targeted grep 锁定可疑 pattern**:针对分类法里的缺陷类用具体 pattern grep(`1e10`、`return 100`、`cv.*==.*0`、`/ float(`、哨兵字段名)。这一步自己用 5-6 个 grep 就能锁定大部分可疑点。
2. **只对锁定的可疑区域派 targeted Explore**(`medium` 级,指定具体 file:line 范围),不扫全仓。
3. **broad Explore 只用于收尾的"全局 CLEAN 确认"**,放最后、范围限定、明确目标为"确认其余干净"(R1 终止依据),而非"找新 bug"。
**反例(iter 50 开头 3 个并行 broad Explore ≈ 7.7M token)**:开头的 broad 扫描是最差投资,只产 2 个真 bug,其余 refuted/不可达。注意:broad Explore 的全局 CLEAN 结论本身有价值(给 R1 收尾信心),所以不是全砍,是改顺序——targeted 先、broad 收尾。
**grep 抓不到的类别**:brace 归属 / scope 层级 / break 退哪层循环(iter 66 ThinWall)需要工具验证(Python brace-counter / 编译实验),不是 grep 能解决的,别误归类。

### 1.5 可达性自检门 — 派 REFUTE 前的过滤器(token 经济 + 防虚假前提)
写完初版方案、派 REFUTE 之前,先花 2-3 个 grep + 读注释做可达性自检。**只用于过滤"路径不可达"类假缺口**——这类派 REFUTE 是浪费(子 agent 会回来告诉你"走不到")。实战:iter 51/51b/63 三次 refuted 都是这类,自检能直接砍掉,省 ~1.1M token。

自检三步(任一失败 → 候选降级为 backlog 或弃,不派 REFUTE):
1. **grep 该函数所有 caller** — 确认生产路径真的调用它(不是被遗忘的内部 helper)。
2. **grep 该字段所有赋值点** — 确认你声称的哨兵值/退化值真能到达消费者(不是被默认值/early-return 挡掉)。
3. **读触发行的注释归属** — 确认约定指向的 struct/字段,和你方案假设的是同一个(iter 51b 把 phase_c 的 SF=0 约定错误嫁接给 FEMResult,就是这步没做)。

**边界(关键,别越界)**:可达性自检**只**判"代码会不会被执行",**不判"这个值/行为对不对"**。后者是分类法/语义判断,自检救不了,**必须派 REFUTE**:
- iter 69 的 1e10 哨兵:路径完全可达(JSON 真输出 1e10),自检三步全过——但方案仍错,因为错在把"合法有利大值"误判成"未评估哨兵"(三种哨兵语义的归类)。这种**语义判别错只有对抗 agent 读 `check_fatigue` 的 infinite_life 逻辑才能发现**。
- 判别标准:候选缺口的本质是"代码会不会被执行" → 自检可判;候选缺口的本质是"这个值/行为对不对、属哪类" → 自检判不了,必派 REFUTE。
- **把可达性当事实**(iter 51/51b/63):agent 报"路径可达"也可能是错的——写最小复现测试当场证伪;复现失败 → 降级 hardening,不声称"修了 bug"。

通过自检的候选才进 Step 2。

### 2. REFUTE — 派对抗子 agent 证伪方案(核心,不可省)
派一个独立子 agent 作为对抗审查者(用你所在环境的子 agent 机制,如 Codex subagent / Claude Agent 工具),prompt 见下。它读源码逐行核实每个前提,**并核对方案是否覆盖了 ⓪ 枚举出的每个 shape 与退化输入格**,返回分级清单。若当前环境无法起子 agent,则做严格的自我证伪(默认怀疑,逐条对照下方核查项)。**「无法起」必须在会话内首次派发前真实探针实测**——陈旧的「不可用」声明 = stale-claim:据其把本应必派的候选(阈值/配置/聚合/跨层类)降级为 self-refuted 的轮,一律视为未 REFUTE(实测:self-refuted 方向否决 0 次,抽样独立复核翻出 2 blocker,且全部命中"必派"类目——绕过点正是无实测的可用性声明)。
若 [blocker] 证伪了整个方向(如发现目标链路是不可达死代码,或方案漏掉整个 shape 且无法补)→ **立即停止,回 Step 1 重选触发点**。

**轻重判据(何时可免子代理走轻量自对抗)**:单分支、无配置/新阈值、有现成回归测试、不跨层 → 可自对抗;触及阈值/配置/聚合/多分支/跨层 → 必须派子 agent。**"看起来简单"不是免派理由**——最险的 BLOCKER 恰恰长在"简单"方案上。

**Tiebreaker 协议(iter 20 实战补全)**:两个对抗 agent 互相矛盾时,**停止派更多 agent,直接查一手源**(docs / spec / upstream 源码 / 规范),把一手源结论记进 journal。"再派第三个 agent"不是裁决——带数字、自信的 agent 也可能错(iter 20 pass A 引真实 3MF 数字主张 mm/min,仍被 PrintConfig.cpp sidetext 证伪)。一手源才是 tiebreaker。

### 3. REVISE
逐条回应:采纳 / 反驳(给理由)/ 列入 backlog。区分「前置 bug fix(纯修复,行为不变)」与「功能改动」,分开提交。

### 4. IMPLEMENT
最小改动集。数值/阈值必须带出处注释。新增配置字段补全:profile 键 + 解析 + 默认值,与既有设计对称。**默认值别选 false/哨兵破坏既有手动构造路径**——尊重现有调用模式,由真实路径显式设值。

**内嵌逐跳追踪(跨层数据改动时强制;此处为唯一权威定义,对抗 prompt 核查项 (i) 引用此处)**:若改动的 datum 跨函数/跨模块传递(id-space、编码、nullness、序列化格式),列出它的完整流向,每跳一行:
```
Datum: <描述>
HOP 1 (produce): <函数> 写 <字段>, space: <id-space/编码>  ✓/✗
HOP 2 (store):   <函数> 透传/转换 ...                      ✓/✗
HOP 3 (slice):   <函数> 读 <字段>, 必须重映射到 <space>      ✓/✗
HOP 4 (consume): <函数> 读并渲染/序列化                      ✓/✗
```
- **任一跳为 ✗ 即 fix 不完整**——不许"在 hop 3 修了就提交,留 hop 4 仍是 ✗"。这正是 bug 被修在一层、在下一层存活、逼用户二次上报的根因。
- **改了任一跳后,重扫下游所有跳**——fix 可能改变 datum 的 shape/长度/编码,破坏原本正确的下游跳。
- **触发范围**:同层局部逻辑改动(无跨层数据)只在改动点验证,不强制列 hops。但**配置字段语义/默认值改动**也算"跨层"——grep 所有读取该配置字段的地方(iter 60 的 9 个消费者就是这么找到的,不是数据流 hops,是配置读取点)。
- **bug 类在同语义字段上重复(横向,跨 struct/跨接口面)**:发现某字段 bug → 立刻查**同语义**字段——不只同 struct 的字段,**更包括同名/同概念字段跨 struct、跨 CLI↔C-API↔JSON↔SDK 的兄弟发射点**。iter 240 修了 `recommendations.overall_score` 却漏了另一个 struct 的 `scores.overall`(同概念跨 struct),49 轮后(iter 289)才补;"兄弟"绑死"同 struct" 是这个漏的根因。iter 70 修了 JSON 侧的 gate 漏了 C-API accessor(同概念跨接口面)是同族。**判别:grep 不限 struct 名,按语义(字段名/概念)grep 全仓所有读取/发射点。**
- **producer/consumer 全集差集扫描(横向的主动版,高 ROI)**:不只是"发现一个查同类"。发现某字段未到达某消费者(或某接口面漏了校验)→ grep producer 的所有赋值,对比 consumer 的所有读取,差集 = 漏接字段族。iter 118→119 一次找到 nozzle_diameter 等一族。比逐个查兄弟更系统。
- **bug 类在同 pipeline 兄弟模块上重复(横向,防假满分跨轮重发现)**:某模块发现假满分/哨兵/退化输入 bug → 立刻查同 pipeline 的兄弟模块的同类退化路径。例如修了 FEM 的 force=0 假满分 → 必查 Phase D 每个子检查、uncertainty、autosuggest 在 force=0 下的行为。**实战教训(force=0 一个退化输入在 7 个模块各产一个假满分,跨 16 轮才扫平)。**

### 5. TEST
为每个语义分支写测试 + 一条回归保护。**跑全套测试**,报告 "X/X 通过（原 N + 新增 K）"。绝不只跑新测试。

**证据纪律(防假绿,取最狠版,此处为唯一权威定义,R3/验证纪律均引用此处)**:用**字符串级证据**核实输出(grep 输出 / JSON 字段 / `strings <binary> | grep <新文本>`),**不依赖构建成功输出或文件时间戳**——增量链接可能不重链:改了源码、构建报成功、但产物没真正重链。改了输出文本后必须字符串级命中验证,没命中就删产物重建。**额外(实战补全):改了 src/X.cpp 后,必须 build 直接消费它的可执行 target,不只 build 测试 target**——iter 29 的编译错误潜伏 3 轮,就是因为只 build `test_core`(不链 main.cpp)、stratum.exe 从没编译。只 build 测试 target = 假绿,与增量链接陷阱同类。**报告层假绿(misleading-success,实战补全)**:`success=true` + `applied==0` / 新 status 不被任何报告循环打印 / opt-in flag 在某路径未透传(iter 121/124/125)→ 用户以为成功实则无效。判别:grep 新 status/flag 在所有 console 打印 + JSON + verify 路径是否被消费。

### 6. RETROSPECT + JOURNAL
对抗复盘:哪些 blocker 在实现前解决、协调了哪些表面矛盾的发现、哪些显式 deferred。按模板追加进 loop-journal,**含 shape 覆盖表与数据流 hops 状态表**。

**变种横向 grep(强制,防同类 bug 跨轮重发现)**:本轮修了一个分类法里的 bug(假满分/哨兵/死代码/退化输入),立即 grep 整个 codebase 找同模式变种——同哨兵值(1e10/0/100)、同退化输入(force=0)、同 clamp、**同语义字段(跨 struct/跨接口面,不限 struct 名)**、同 pipeline 兄弟模块。发现全部入本轮或紧接的下一轮,**不许靠 backlog 一轮轮串**。

**Pattern Index 维护(强制,若 journal 维护了主题级索引)**:本轮若发现新的可复用 pattern(新哨兵语义、新配置债、新可达性陷阱、新项目约定、新假乐观变种)或新 rationalization,在 Pattern Index(或等价的主题级索引,通常在 journal 末尾)对应子节追加一行:`- **<稳定关键词>:一句话 + iter 编号>`。**用稳定英文技术词作关键词**(`sentinel`、`false-perfect`、`config-dual-store`、`reachability-trap`、`false-optimistic`),不用容易漂移的中文描述——措辞漂移会让未来轮的 grep 静默失效(Step 1 已点明此坑)。只追加不维护 = 几个月后过期,和静态快照一样废。

**机械完成标志(防无声跳过,实战补全)**:iter 130–295 约 165 轮只有 1 条进 Pattern Index(<1%)——"强制维护"被无声跳过。反制:**每轮 journal 末尾必须显式写一行 `Pattern Index 更新: N/A | 新增 <关键词>`**,没有这行 = 本轮未完成。连续多轮 N/A 是 R4 信号(真没新 pattern,或没在识别),审计痕迹比无声跳过强。

**淘汰规则(防 Pattern Index 自身膨胀,批次收尾时执行)**:只增不减 = 把 journal 膨胀转移到索引,延迟爆炸。**项目约定类**(哨兵语义、config 双存储债、reachability 陷阱、两态决策、trust gate 范式)寿命长,长留活跃索引;**已修 bug 清单类**寿命短,修复稳定后(如一次 DOGFOOD 全绿)移到末尾「历史修复档案」子节——grep 仍命中(防重提),不污染日常扫描注意力。

## 目标缺口清单(PLAN 阶段按此扫描)

- **合法状态空间未枚举**:数据能取多个 shape,方案只处理了其中几个(unknown unknowns)。先做 Step 0。
- **假满分**:缺数据/退化输入返回满分,把"不可观测"标成"完美一致"(cv=0、空集→0、!has_data→100)。**判 trap 前先 grep 该字段所有消费者**(iter 28):若消费者语义是 `>0 passed`,100 是合法刚性体钳位,不是 trap。**哨兵值(1e10/0/99/100)各有三种语义**(iter 69):未评估/合法有利值/已评估不主导——归类再改,别一刀切 null。
- **假乐观(false-optimistic,假满分的隐蔽变种,实战高频)**:无效/未缩放输入被静默接受,跑出**偏高但有限**(非满分 100 也非哨兵 1e10)的结果。不触发哨兵值检查,更难抓。触发机制是"输入维度被静默折叠":未知 pattern 回退全实心刚度→SF 系统性高估(iter 293);PETG/ABS 走 PLA 硬编码模量→数值偏高(iter 199);温度死区(15-25C 全 1.0)→老化偏慢误报(iter 202);z-ratio>1.0 物理不可能值静默接受→SF 虚高(iter 294)。**判别:输入空间有未校验/未缩放维度时,查该维度被折叠到什么默认值——若折叠到物理上偏乐观的默认,就是假乐观。**
- **数据已解析未消费**:parser/CLI/loader 提取了但逻辑没用。**强制检测(实战补全,iter 265 最严重)**:对涉及的 config/result struct 字段,grep 其 reader 数——**producer>0(有赋值点)且 reader==0(无读取)的字段必入本轮或 backlog**。iter 265 的 `--service-time` 解析了但 `aging_time_hours` 从未赋值、整条接线断裂、env_aging 模型门恒不触发、JSON 五字段永远 null——纯 grep 本应能抓。也含 CLI flag 解析了变量却从不流入下游门的极端形态。
- **退化输入二义性**:0 既能=完全一致,也能=空/不可比较。
- **单维度简化**:阈值只看一个物理量,忽略该量实际依赖的其他变量(耦合被折叠掉)。这类耦合在每个领域都不同——先问"这个阈值的物理量在真实场景里还依赖什么",优先扫反复出现的耦合点。
- **数值无出处**:阈值/魔数没依据,且与该领域公认默认/规范矛盾。
- **死代码**:条件计数被无条件覆盖、防御字段在真实路径不可达。**死代码活化前必校验阈值**(iter 57):长期 N/A 的分支要激活时,其阈值是在死状态下定的,活化前用代表性真实输入跑一遍,防批量误报。
- **文档/注释漂移(stale-doc,死代码的文档变种,实战高频)**:代码改了,注释/MANIFEST/roadmap/journal 自身没同步——注释谎称实现机制(iter 202 注释 Arrhenius 实现却 Q10)、MANIFEST 滞后 4 个版本(iter 264)、注释引用已被推翻的旧设计(iter 267/268)。**机制:改代码时必 grep 同模块注释/MANIFEST 的同语义站点同步。** 警惕 post-hoc 合理化注释(伪造出处,iter 241)。
- **对称性 bug**:同一概念在多处用了不同来源(如输出标签用配置默认值,而同函数用的阈值却用了运行时解析值,两者不一致;或检测边界用探测值、评分用配置值,不同步)。极易在"读代码不精确"时漏掉。**判对称性前先 grep 证明两 site 共享数据/消费者**(iter 51 虚假耦合):"1/lh vs ×lh 方向相反"≠ 逻辑矛盾——两公式可能无数据共享,是独立设计。
- **单层修复**:bug 报在 layer N,只修 N 不追 N+1/N+2(UI 文本、缓存、preview),同一份错数据在下游继续被错读。
- **配置卫生**(四子类,逐一核查):
  - **键完全缺失**:某分支/某变体的配置键不存在(如某枚举值有内部阈值却没暴露对应配置键,只有其中一个变体暴露了)。
  - **作用域不匹配**:新键挂全局配置,被它影响的字段却按变体/实例分(调一个全局值带歪所有变体)。
  - **覆盖优先级未定义**:用户值被 auto-detect/默认无条件覆盖(用户在配置里设的值静默失效)。
  - **sentinel 缺失**:无法区分"用户显式设的值"vs"结构体默认值"(POD struct 无 was_set 标志 → "尊重用户值"方案不可表达)。
  默认优先级规则:**用户全局只能加严(用 max),不能放松物理/安全下限**。

## 诚实性硬原则(贯穿所有步骤)

1. **缺数据/退化输入的两态决策(核心,实战最易混)**:先判清属于哪一态,动作完全不同——
   - **真·不可观测**(输入根本没产出该信号:缺少必需注解/元数据、样本数低于统计下限、字段从未被写入)
     → `assessable=false` / score=null,**退出总分并重算权重**。定义消费者契约(调用方先查 `assessable`,聚合器排除而非平均)。
   - **有数据但信号不可靠**(聚合方式丢失关键区分——如运行平均把有意策略稀释成噪声;或落入判别盲区无法归类;或值域无法区分"缺失"与"合法零值")
     → **保持分数不降**,只改 evidence(verdict 声明局限 + recommendation)。降分会用 false-positive 风暴换更危险的 false-negative。

   **双向陷阱**:「无数据」既不是 100(假满分 = false-positive),也不是 0(假最差 = false-negative,对检测工具更危险,会把整份报告钉到地板)。真不可观测的唯一诚实答案是退出总分;信号不可靠则不降分、诚实声明。**判错这一态 = 方案方向错**(典型误判:把"信号不可靠"当成"不可观测"→ assessable=false → 漏报真实缺陷)。
2. **区分 evidence(人读,可声明不确定)vs verdict(机器消费,改动有副作用)**:优先只改 evidence,不静默改 verdict。
3. **回归检测工具里,漏报(false-negative)比误报更危险**——默认偏保守误报方向。
4. **魔数/阈值必带出处注释**(优先级规则见缺口清单配置卫生末行)。
5. **范围控制**:本期不处理的同构问题显式列入 backlog,不许偷偷修一半;**backlog ≠ 完成**,下轮重新评估。

## 迭代元规则(跨轮,治循环本身)

- **R1 — 一轮须在新维度产出新发现,否则扩张边界(双向)**:一轮只是重扫已审过的维度且无新发现,不是进展,是 comfort。连续 2 轮无新发现 → 停止扫描,沿**两个方向**扩张:
  - **模块级扩张**(现状):重枚举 shape(Step 0),或挑一个 NOT UNDERSTOOD 的 shape 读它的 producer。
  - **变种级扩张**(实战补全,防假满分跨轮重发现):已发现的缺陷类(假满分/哨兵/退化输入),在所有平行消费者模块里 grep 同变种。iter 67 在已扫过的检测器维度判"无新缺口",iter 68 却在完全不同的退化输入维度找到真 bug——根因就是只做了模块级、没做变种级扩张。
- **R2 — 用户报的 bug = 某个 shape 或某跳被漏**:别只修报告点。先定位是哪道防线失败(Step 0 漏了 shape?Step 4 漏了跳?),修根因 + 重追全流——漏一跳常意味着相邻跳也漏了。
- **R3 — "build green"是必要非充分**:绿了只证明编译链接通过,证明不了数据流正确。不许用绿构建关闭一轮还没逐跳追完的 fix。(与 Step 5 证据纪律一致,此处为元规则口径。)
- **R4 — 置信度校准**:静默轮次越多,置信度应**下降**而非上升——每轮无新发现都提高"你在认知边界内扫描而非扩张边界"的概率。多轮安静后高置信是 smell,不是 done 信号。

## 验证纪律补充(Step 5 之外)

Step 5 已定义证据纪律(字符串级、不信时间戳、build 可执行 target)。此处只补 Step 5 未覆盖的:

- **greenfield / 无既有套件时如实说明,不要编造 "原 N"**(编造基线 = 假证据)。
- **E2E 用真实 fixture,非仅单测**;且**断言数值变化前,先用 fixture 跑改动前/后两次,确认输出真变了**(fixture 敏感性,iter 48/57/66 踩坑:cube λ 太低、thin_plate 顶点不够,名字暗示能行 ≠ 真能行)。**全 PLA/全默认参数 fixture 盲点**:若所有 fixture 共享同一材料/参数(全 PLA / lh=0.2 / nozzle=0.4),材料或参数相关的 dormant bug 对它们集体不可见(零差异 ≠ 无 bug)——需构造差异化 fixture 或靠代码路径分析(iter 118/124/125)。
- 若 E2E 证伪了 PLAN 的前提,如实记录(如"X 必然发生"实则不发生)。

### 5.5 DOGFOOD(周期性,非每轮)— 真实消费者样本,非仓库内 fixture
每 N 轮或每个 milestone,用**真实消费者产物**(真实 OrcaSlicer 导出的 3MF / 用户报的输入 / 真实硬件配置)跑一次,而非仓库内自制 fixture。iter 44 教训:仓库内 fixture 全绿,真实 SnapMaker Mega+Starmie 的 3MF 一跑就抓到代码审查 + backlog 全漏的用户面 bug(验证器硬要求 `process_settings_1.config`,但真实导出可能只有 `project_settings.config`)。**fixture 覆盖 ≠ 真实覆盖**——代码层对抗抓不到这类 bug。**SDK/库变更时,用 minimal `find_package` 消费者 E2E**(不只 test_core),验证 install-export / 头文件 / 链接接口(iter 145:test_core 不链 install 接口,抓不到打包回归)。

| "对抗 agent 给 PASS 了" | 对抗只攻 known unknowns。你和它都不知道 shape D 存在 → 它不会问 → PASS 漏 D 的方案。先枚举(Step 0)。 |
| "复用了类型 X(checklist PASS)" | 复用 ≠ 理解全部合法状态。4 个 shape 只懂 2 个,"复用了"照样漏另 2 个。shape 枚举才抓得到。 |
| "layer N 修了 bug,搞定" / "这字段修对了,其他没事" | 同份数据在 N+1/N+2 被错读;同语义字段(跨 struct/跨接口面)、同 pipeline 兄弟模块常犯同样错。Step 4 横向 grep。 |
| "权重表看起来对" | 数值碰巧相等掩盖索引错位/重复项。加 `static_assert` 对齐 维度数==权重数。 |
| "这段字段防御性加上就好" | 真实路径不可达 = 死代码。先验证可达性(iter 63 用复现测试证伪可达性)。 |
| "降级 verdict 减少误报" | 漏报 > 误报(回归工具)。只改 evidence,保留 verdict。 |
| "X 必然触发(如大数据量必然触发采样)" | 想当然。阈值单次 vs 全程聚合——E2E 会证伪。 |
| "方案里的行号/现状我记得是 X" | 未核实 = 偏移。现状描述错比方向错更隐蔽(iter 50/68/69)。file:line 核实 + REFUTE 核查项 (j)。 |
| "范围小不用对抗" | 看似简单也踩分界/默认值。小改动走轻量自对抗。 |
| "多轮没新发现,差不多该收了/挺稳的" | R4:静默轮越多置信度应降不是升。R1 双向扩张(模块级 + 变种级)再谈收尾。 |
| "agent A 带数字、很自信,应该对" | iter 20 两 agent 互相矛盾,带数字那个也错。一手源(docs/spec/upstream)是 tiebreaker,不是第三个 agent。 |
| "journal 里写了 X(文件数/测试数/轮次结论),那就是 X" | journal 自身也会漂移:iter 172 closeout 的 76/44/5 是伪事实、iter 264 记 56 文件实测 55、iter 162 backlog 记 24/32 实测 32/32。Step 1 grep journal 命中数字时,**数字类陈述复核一手源**(git show / 重新实测),别当一手源。 |

## 已知结构局限:自证步骤无独立验证(诚实标注,需维护)

skill 的大部分步骤(ENUMERATE、横向 grep、可达性门 Step 1.5、Pattern Index 维护)是**自证型**——执行端自己 grep、自己判、自己报告,**没有独立验证**;只有 REFUTE 派子 agent 是独立验证。这是 token 经济下的刻意取舍,但代价真实:

- **iter 240 漏 `scores.overall`(横向 grep 关键词选窄)→ 存活 49 轮 → iter 289 靠 E2E 碰巧打印 67.58 才抓到**——若 E2E 没覆盖,永远漏。兜底是概率性非保证性。
- **Pattern Index 机械完成标志在 295 轮 journal 里从未被执行**(grep 命中 1 次)——skill 自己定的规则自己不执行,自证步骤的"通过"不可信。
- **iter 293/294/289 三轮标"轻量自对抗",无一被独立验证抓住**;**Gcode-diff 2026-08 量化锚点:self-refuted 方向否决 0 次,抽样 7 轮 independent-REFUTE 翻 4(2 blocker)——"self-refute ≈ 没做 REFUTE"不是理论,是实测**。

**含义**:不要把自证步骤的"通过"当 REFUTE 级可信度。横向 grep"无兄弟字段"≠ 真没有(可能关键词选窄);可达性门"通过"≠ 真可达(可能 grep 漏 caller)。**对触及阈值/配置/聚合/跨层的改动,自证不够用,必派 REFUTE**——这是把概率性兜底升成机制性验证的唯一手段。无子 agent 环境下此局限恶化:REFUTE 退化为自我证伪(= 自证),核心对抗机制失效。发现新的"自证失效→延迟发现"案例,追加进上面实证列表(带 iter 号)。

## Red Flags — 看到就停,回到对应步骤

- **想提前收口 / 缩减用户给的轮次或范围** → **回核心原则「用户指令是硬约束」**。先问:用户给过明确数字吗?给了就照做。任何"我觉得够了/自然收口了/后面会低价值"的念头,在用户没说停之前 = 违约。这条比下面所有都优先。
- 想跳过 ENUMERATE 直接 PLAN(且改动涉及合法状态空间)→ **回 Step 0**。
- 想跳过 REFUTE 直接实现。
- "我已经心里 review 过了"。
- "实现完再补对抗也一样"(实现后的 review 是审 diff,不是证伪方案,两回事)。
- "方向感觉对,blocker 以后再说"。
- 修了 layer N 就想提交,没追 N+1/N+2 → **回 Step 4 逐跳追踪**。
- 多轮无新发现却觉得"挺稳了" → **回 Step 0 重枚举**(R1 双向扩张,不是停)。
- "Pattern Index 这轮先不更新,批末一起补" → **回 Step 6 当轮做**。批次收尾是兜底,不替代单轮;用"批末补"合理化单轮跳过 = 和"实现完再补对抗"同级的流程违规。
- **以上任何一条 = 停下,回到对应步骤。**

## 终止条件

**前提:终止条件服从用户指令(核心原则)。** 用户给了明确轮次/范围数字时,下面的 STOP 不能单方面提前结束;只在没给数字、或已达到所给数字时生效。

**下限(R1 的安全阈)**:连续 2 轮 PLAN 找不到新理论缺口,且 Step 0 重枚举后仍无新 shape、无 NOT UNDERSTOOD 项可读,则本轮 STOP。

汇报累计:测试增量、文件数、累计 blocker/major、backlog 清单、shape 覆盖表、数据流 hops 状态。

## 批次收尾(每 ~20 轮 / 会话边界)— 兜底蒸馏 + 归档

**这是兜底,不替代单轮 Step 6**——用"批末补"合理化单轮跳过 = 流程违规。批末五件事:**Pattern Index 查漏追补**(扫本批每轮更新栏,补漏标/漏提炼)→ **原始轮次物理归档**(切到 `loop-journal-iterNNN-NNN.md`,活跃文件只留当前批;归档 ≠ 删除,grep glob 仍跨批可达)→ **盲区回收问一句**(本批有无分类法没覆盖的反复失败模式 → Pattern Index「Skill 流程适配」种子)→ **收尾声明机械重算**(closeout 直方图/计数按各轮「验证级别」标记重算,审计产物不是宣传产物)→ **工作区卫生**(临时产物清理,`git status` 干净)。重心是蒸馏不是归档:真正的减法只有"把散在 N 轮的教训压成 Pattern Index 一行"。细节见 `references/framework-manual.md`「批次收尾规程」。

## 框架结构(Standard Framework Layout,速览)

AgentSkills 开放标准布局:**领域无关验证内核(本文件,每轮全量加载)+ 可插拔领域包(`assets/meta-bench/seeds/<domain>/`)+ 自评测工具链(`scripts/run_meta_bench.py --verify/--list/--score/--demo`)+ 框架手册(`references/framework-manual.md`,条件性读取:采纳框架/加种子/同步安装/**改本文件**时读)**。**分类法(缺口清单/自欺表/对抗 prompt/诚实性原则)属内核,禁止迁出**;领域包只放领域特化案例与种子。目录树、manifest schema、发行/同步(含 shadow 警告)见手册。
