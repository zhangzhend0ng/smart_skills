# Adversarial Development Loop · 对抗式自循环开发

## 核心原则 (Overview)

**任何方案在写下一行代码之前，必须先被一个独立审查者成功证伪过——或至少尝试证伪后幸存。** 决策要经得起对抗，而非依赖实现者的自信。每轮迭代 = 一次「规划 → 对抗证伪 → 修订 → 实现 → 测试 → 复盘」闭环，并当场落盘成日志。

**铁律：跳过对抗步骤 = 流程违规。未经对抗的代码应推倒重来。**

**违反规则的字面，就是违反规则的精神。**

## When to Use / 何时使用

适用：
- 实现/修改「结论会被机器或人当真消费」的逻辑：评分、检测、诊断、阈值判断、回归工具。
- 方案含理论缺口、拍脑袋阈值、退化输入二义性、未验证前提。

不适用：单行 typo、纯研究无实现、有测试即可保护的机械重构。

## 一轮迭代（6 步，全部走完）

```
 ① PLAN 找理论缺口 → 写初版方案（先不实现）
        │
 ② REFUTE 派对抗子 agent 证伪【尚未实现】的方案 ──┐
        │                                          │
   [blocker 证伪整个方向？]                        │
     是 ──→ 停止本方向，回 ① 重选触发点（别在死链路投入）
     否 ──→                                        │
        │ ←──────────────────────────────────────┘
 ③ REVISE 逐条：采纳 / 反驳(理由) / backlog；区分「前置bugfix」与「功能」分开提交
        │
 ④ IMPLEMENT 最小改动集；数值带出处注释；新配置键补全(对称)
        │
 ⑤ TEST 每个语义分支 + 回归保护；跑全套 → "X/X（原 N + K）"
        │
 ⑥ RETROSPECT + JOURNAL 对抗复盘 + 按模板追加日志
        │
     终止条件？ → 否：回 ① 开下一轮
```

### 1. PLAN — 找理论缺口
按下方「目标缺口清单」扫描代码，锁定本轮触发点。写初版方案，**先不实现**。

### 2. REFUTE — 派对抗子 agent 证伪方案（核心，不可省）
派一个独立子 agent 作为对抗审查者（用你所在环境的子 agent 机制，如 Codex subagent / Claude Agent 工具），prompt 见下。它读源码逐行核实每个前提，返回分级清单。若当前环境无法起子 agent，则做严格的自我证伪（默认怀疑，逐条对照下方核查项）。
若 [blocker] 证伪了整个方向（如发现目标链路是不可达死代码）→ **立即停止，回 Step 1 重选触发点**。

### 3. REVISE
逐条回应：采纳 / 反驳（给理由）/ 列入 backlog。区分「前置 bug fix（纯修复，行为不变）」与「功能改动」，分开提交。

### 4. IMPLEMENT
最小改动集。数值/阈值必须带出处注释。新增配置字段补全：profile 键 + 解析 + 默认值，与既有设计对称。

### 5. TEST
为每个语义分支写测试 + 一条回归保护。**跑全套测试**，报告 "X/X 通过（原 N + 新增 K）"。绝不只跑新测试。

### 6. RETROSPECT + JOURNAL
对抗复盘：哪些 blocker 在实现前解决、协调了哪些表面矛盾的发现、哪些显式 deferred。按模板追加进 loop-journal。

## 对抗子 agent 的 prompt 模板（核心，原样复用）

```
你的唯一任务是推翻下面这个【尚未实现】的方案，不是审查已有代码。
读相关源码逐行核实每个前提。对每条发现打分：
  [blocker] 会让方案错误 / 埋配置歧义 / 逻辑不可达 / 有未定义行为
  [major]   设计缺陷、数值无出处、过度简化、死代码、对称性破坏
  [minor]   文本漂移、命名、注释
特别核查：
  (a) 方案的前提在真实路径是否成立（是否是不可达死代码？）
  (b) 魔数/阈值有无出处，且与既有默认值一致
  (c) 有无被无条件覆盖的死代码、被巧合掩盖的索引错位/重复项
  (d) 配置键是否与既有设计对称、优先级是否定义（用户值会不会被静默覆盖）
  (e) 是否会用 false-positive 换来更危险的 false-negative
禁止客气，默认怀疑。返回分级清单 + 事实校验结论（引用 file:line）。

【待证伪方案】：<粘贴 PLAN 阶段方案>
```

## 目标缺口清单（PLAN 阶段按此扫描）

- **假满分**：缺数据/退化输入返回满分，把"不可观测"标成"完美一致"（cv=0、空集→0、!has_data→100）。
- **数据已解析未消费**：parser 提取了但逻辑没用。
- **退化输入二义性**：0 既能=完全一致，也能=空/不可比较。
- **单维度简化**：阈值只看一个物理量（忽略材料/喷嘴/层高/温度耦合）。
- **数值无出处**：阈值/魔数没依据，且与切片器/框架默认矛盾。
- **死代码**：条件计数被无条件覆盖、防御字段在真实路径不可达。
- **配置卫生**：profile 键缺失、优先级未定义、与对称设计不一致。

## 诚实性硬原则（贯穿所有步骤）

1. **不可评估维度退出总分并重算权重**，标 `assessable=false` / score=null（或 NaN，让下游聚合器强制报错而非静默误读），并定义消费者契约（调用方必须先查 `assessable`，聚合器必须排除而非平均）。绝不用中性分/假满分糊弄（70 是拍脑袋，且常踩在分界上）。**双向陷阱**：「无数据」既不是 100（假满分 = false-positive），也不是 0（假最差 = false-negative，对检测工具更危险，会把整份报告钉到地板）。唯一诚实答案是退出总分。
2. **区分 evidence（人读，可声明不确定）vs verdict（机器消费，改动有副作用）**：优先只改 evidence，不静默改 verdict。
3. **回归检测工具里，漏报（false-negative）比误报更危险**——默认偏保守误报方向。
4. **魔数/阈值必带出处注释**；优先级用 max（用户全局只能加严，不能放松下限）。
5. **范围控制**：本期不处理的同构问题显式列入 backlog，不许偷偷修一半。

## 验证纪律（TEST / RETROSPECT）

- 跑全套测试，报 "X/X（原 N + K）"。**greenfield / 无既有套件时如实说明，不要编造 "原 N"**（编造基线 = 假证据）。
- E2E 用真实 fixture，非仅单测。
- 用**字符串级证据**核实（grep 输出 / JSON 字段），**不依赖文件时间戳**（增量链接可能不重链 → 必要时 rm exe + 重建）。
- 若 E2E 证伪了 PLAN 的前提，如实记录（如"X 必然发生"实则不发生）。

## Rationalization Table（对抗复盘真实抓到的自欺）

| 借口 / 自欺 | 现实 |
|---|---|
| "给个中性分 70 就行" | 中性分是假满分换假中性分，仍是无信息数值却污染总分。正确做法是退出总分并重算权重。 |
| "n=1 时 stddev 数学上良定义、=0，所以 100 是对的" | 数学为真 ≠ 语义为真：单个样本无法体现「稳定或不稳定」，σ=0 是退化而非「完美一致」。这是假满分最常见的学理化辩护（baseline 实测）。 |
| "空输入返回 0 就行，反正标了 cannot score" | 对检测工具，「无数据→0」是更危险的 false-negative，会被下游当真分数钉到地板。无数据既非 100 也非 0，必须退出总分。 |
| "这个阈值我记得是 X" | 无出处 = 拍脑袋。必须检索出处（如官方调优指南）或显式标 v1 粗粒度模型。 |
| "权重表看起来对" | 数值碰巧相等会掩盖索引错位/重复项。加 `static_assert` 对齐 维度数==权重数。 |
| "这段字段防御性加上就好" | 真实路径不可达 = 死代码，浪费且误导。先验证可达性再决定。 |
| "降级 verdict 减少误报" | 漏报 > 误报（对回归工具）。只改 evidence 声明不确定性，保留 verdict。 |
| "X 必然触发（如 56万点必然采样）" | 想当然。核实阈值是单次还是全局——E2E 会证伪。 |
| "范围小不用对抗" | 看似简单的改动也可能踩分界/默认值。小改动也走轻量自对抗。 |

## Red Flags — 看到就停，回到 REFUTE

- 想跳过 REFUTE 直接实现。
- "我已经心里 review 过了"。
- "实现完再补对抗也一样"（实现后的 review 是审 diff，不是证伪方案，两回事）。
- "方向感觉对，blocker 以后再说"。
- **以上任何一条 = 停下，回到 REFUTE。**

## Loop Journal 条目模板

```markdown
## 迭代 N — <主题>
### 触发的理论缺口
### 初版方案（被推翻点）
### 对抗审查结论（[blocker]/[major] 清单）
### 修订方案（逐条 采纳/反驳/backlog）
### 改动文件
### 测试证据（X/X，原 N + K）
### E2E 证据
### 遗留 backlog
```

## 终止条件

连续 2 轮 PLAN 找不到新理论缺口，或本轮 STOP。汇报累计：测试增量、文件数、累计 blocker/major、backlog 清单。

## Common Mistakes

- **对抗 agent 去审已有代码**而非证伪未实现的方案 → 失去"实现前推翻"的价值。prompt 必须写明"尚未实现"。
- **只改了一个序列化点** → 全面 grep 所有消费者（典型：第二个 JSON/Markdown 渲染块被漏）。
- **默认值选 false** 破坏既有手动构造路径 → 默认值要尊重现有调用模式，由真实路径显式设值。
- **把 backlog 当完成** → 显式 deferred ≠ 已解决，下轮要重新评估。
